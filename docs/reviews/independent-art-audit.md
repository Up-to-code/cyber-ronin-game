# Independent art and animation audit

2026-11-11. Read-only product audit; report and evidence images are the only additions. Scope: the visible ronin, rig atlas, kick/sword motion, and continuity with the supplied character pack. No asset regeneration, controller changes, or replacement game. The user's rejection of the artwork/motion is the acceptance context, not a finding that numerical rig checks can overturn.

- Read the generate2d-assets-clean-align, kill-game-slop/art-content-coherence, and 2dimg2motion/keypose-redraw guidance. Their relevant gate is that structural validation does not establish visual acceptance; large silhouette/perspective changes need redrawn poses rather than rotated cutouts.

## Conclusion

The major mismatch is representational. The new rig solves where joints go in a 2D plane, while the artwork needs to describe how a clothed volume turns, compresses, overlaps, and carries a sword. A valid chain of joints does not answer those drawing questions. Improving IK alone will retain the current puppet appearance.

The new design also is not a faithful continuation of the original character. The source has a slim armored body, long narrow boots, a broad torn cape, compact hat, and a fine curved cyan-edged katana. The generated atlas has bulky wrapped cloth sleeves, large buckled glove/boot forms, a short layered belt skirt and a separate narrow tail. Shared dark/teal colors and a conical hat establish the same genre, not the same character. This is a confirmed visual difference; whether a deliberate new design is acceptable remains a human decision.

A crucial provenance correction: the original kit is **painted, not pixel art**. Its bundled README says this at lines 5–6 and prescribes linear filtering at 82 and 95–97. The [creator's source page](https://pavelekh.itch.io/cyber-ronin-sprite-pack) independently states the same. Calling its downsampled/quantized derivative the original pixel art obscures what was changed. Restoring the source faithfully and choosing a new pixel-art direction are two separate production choices.

## Why slicing and rotating can help, and where it stops

Cutouts can serve restrained breathing, distant background actors, a deliberately flat puppet style, small cape motion, or limited side-on limb swings with overlapping caps. They also remain useful for debug sockets and hit origins. They cannot invent a boot sole, shortened thigh, turned pelvis, changed sleeve fold, hidden arm, or new hat underside. Those are new drawings. A weighted mesh could reduce seams and bend cloth, but still cannot recover unseen surfaces from one illustration; it is an engineering investment, not a guaranteed art fix.

Here the current boot/hand end nodes are explicitly placed with angle zero. This keeps the standing boot stable but leaves the raised kick boot upright and the sword glove unresponsive to grip rotation. Simply allowing rotation would address that one constraint while rotating the same lighting and silhouette. Likewise adding more joints will not restore the source's cape, slim armor, or pose-specific foreshortening.

## Recommended production path for one small vertical slice

1. Freeze expansion. Keep the level, collision body, gameplay timings, input and damage rules. Select one ronin and one guard on a short section of existing ground. Preserve the rejected capture as the baseline.
2. Make the art decision visible: compare original painted source at intended size against one genuinely approved new pixel baseline. If continuity with the provided character matters, use the original as the identity authority. Do not adopt the generated parts as authority merely because they are rigged.
3. First implement/review only idle→one sword attack→recovery and idle→one kick→recovery, both facings, plus a short run stop. Reuse the kit's whole-body sword animation as an A/B reference where its motion matches the rule. The existing kit lacks a documented kick clip; do not relabel a sword animation as kick.
4. For a new kick or changed sword action, author whole-character key poses as a coherent set using the chosen baseline reference. Approve silhouette and hand topology before in-betweens. If using image generation, follow the shared-sheet identity lock and reference-guided redraw contract; do not manufacture the poses by rotating the baseline. A human pixel animator can instead draw/clean the same keys. Neither workflow guarantees acceptance without review.
5. Fit frame durations to the action contract, map a socket per key/frame where effects need it, and keep the authoritative collider separate. Test native-size motion with FX off, then restore FX and inspect the actual stage. Only after explicit human acceptance expand to charge, plunge, aerial attacks, enemy variants and reuse.

| Option | Benefit | Cost / risk |
|---|---|---|
| Faithful original painted frames + minimal new full-body kick | Fastest concrete continuity comparison; existing attack families and timing metadata | Style differs from a strict pixel-art direction; missing actions need matching work; source pack's claims are not proof every frame passes this game's tests |
| Approved new pixel baseline + complete pose redraw for two actions | Can establish a coherent genuine pixel language and readable action silhouettes | More drawing/generation review and cleanup; generation can drift; higher cost per new action |
| Salvage current rig with new part views, hand poses, layer switches and pose library | Reusable sockets; limited procedural variants; less frame storage | Still needs substantial art authoring; high engineering/art coupling; least promising immediate path after the user's rejection of this puppet approach |

Recommendation: use the first option as a bounded comparison if the user still wants the original identity; choose the second only after the new baseline is accepted. Do not build a larger procedural rig before the two-action proof. Technical checks remain necessary for attachment/contact regressions, but the art gate is an observed, human-approved result.

## Professional reference basis

- [PavelEKh, Cyber Ronin Sprite Pack](https://pavelekh.itch.io/cyber-ronin-sprite-pack): primary source for style, supplied animations, pivots and intended filtering. Local files were inspected rather than relying on marketing claims of smoothness.
- [Pedro Medeiros, Basic Aseprite Animation](https://saint11.art/pixel_art_articles/article3/): explains pose-to-pose drawing, frame duration, anticipation and maintained volume. Applied here as a review method for action keys and timing, not as a mandate to squash a samurai like a bouncing ball.
- [Pedro Medeiros, Basic Shading](https://saint11.art/pixel_art_articles/article4/): describes drawing material/light relative to form, choosing a light direction, and prioritizing readability at low resolution. This supports inspecting the turning form rather than assuming an unchanged rotated highlight describes it.
- [Pedro Medeiros, Pixel Art Tutorials](https://saint11.art/blog/pixel-art-tutorials/): primary tutorial collection and professional practice reference. No claim that copying its effects or adopting a standard palette automatically fixes this character.

## Explicit unknowns

No live input, continuous audio/video playback, physical-phone viewing, new animation trial, or human preference test was performed. The audit cannot certify timing feel from sampled stills. The exact image reference supplied to generation is not proven by the saved prompt alone. Desired final painted-versus-pixel direction and permission to redesign the character remain product decisions. Complete enemy family continuity, death motion and equipment switching are outside this sample. No UI files were changed, so the Rams-after-UI-edit instruction was not triggered by this report.
