# Walk, run and jump presentation

The player has one movement speed: 300 world pixels/second, with no separate RUN control. The legacy `sprint` action is still accepted but no longer changes speed, because mobile has no room for a second movement button. The `run` SpriteFrames play at that speed; a cycle is not restarted each physics tick, and the supplied detailed clips play at a base 2× rate to match travel at the existing world scale. Attacks retain their 0.42-second action / 0.12-second contact window, and jump/attack/hurt pose ownership is preserved.

Footstep cues follow two cycle markers (frame zero and the middle frame), with a short debounce when a gait changes. The markers approximate two contacts in the supplied loop, rather than sounding on every animation frame. Running emits a small `step` dust event on every third contact; the main scene maps that event to its small-dust presentation. Patrol guards use a slower walk cycle and nearby footsteps; chasing guards use run. An airborne guard holds a falling pose instead of continuing its previous ground cycle.

Jump ascent/apex/descent remain physical-phase pose holds. A stationary landing briefly holds a recovery pose, and a dive (`DOWN`+attack) holds its landing pose after touchdown instead of reverting to the dive. Takeoff and landing add small, quickly settling visual scale changes around the drawn character's foot origin, carried on the visible cel rig as well as the sprite; collision never scales. Damage clears the landing/takeoff presentation. Call `reset_motion_presentation()` on restart or level transition to clear cadence, squash and takeoff state, then set `map_width` to the level's width so character bounds work beyond the old 2520-pixel arena.

`game/tests/locomotion.gd` passes in Godot 4.7.2: single movement speed including no effect from legacy sprint input, advancing cycles, sparse cadence-linked dust, rise/fall poses, grounded landing squash on the visible rig and its exact settle, air `J` versus `DOWN`+`J` ownership, hurt cancellation, visual reset, configured map bounds, and guard falling/landing presentation. Native rendered motion in the complete newly integrated maps still needs the parent agent's final capture; these assertions do not establish subjective animation quality or physical-phone behavior.
